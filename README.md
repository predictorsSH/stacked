# Stacked

영어 기술 글을 매일 조금씩 읽으며, 기술과 영어를 함께 익히는 개인 읽기 도구.

## 왜 만드나

좋은 기술 글은 대부분 영어로 먼저 나온다. 하지만 영어 원문은 읽는 데 시간이 오래 걸려서 미루게 된다.
게다가 기술 이야기는 하루에도 수백 개씩 쏟아지고, 그중 진짜 읽을 가치가 있는 글은 일부다.

Stacked는 Hacker News에 올라온 글을 모아, 짧은 영어 요약과 해당 요약을 독해하기 위한 보조 정보를 함께 보여준다.
막히는 문장만 잠깐 한국어로 확인하고 다시 영어로 돌아오게 해서, **기술 글 읽기 습관과 영어 공부를 동시에** 잡는 것이 목표다.

## 핵심 경험

1. **요약 (영어, 5문장 이내)**: 글의 핵심을 영어로 빠르게 파악한다. 옆에는 요약을 이해하는 데 필요한 핵심 표현과 뜻이 표시된다.
2. **자세히 보기**: 더 긴 영어 요약과 HN 댓글의 주요 의견을 본다. 여기도 핵심 표현이 옆에 표시된다.
3. **원문 링크**: 더 읽고 싶으면 원문으로 이동한다.

**번역 방식**: 영어 문장을 길게 누르는 동안만 그 문장이 한국어로 보이고, 손을 떼면 다시 영어로 돌아온다.


## 수집 소스

| 소스 | 사용 여부 | 이유 |
|---|---|---|
| Hacker News | ✅ 사용 | 영어권 개발자 커뮤니티. 한국어 사용자에게 영어 글을 요약·학습 자료로 제공하는 것 자체가 Stacked의 가치가 된다. 점수·댓글 수는 중요도 신호로 쓸 수 있다. |
| 긱뉴스 | ❌ 제외 | 한국어 사용자에게 한국어 요약을 이미 제공한다. Stacked와 역할이 겹친다. |

**소스 선정 원칙**: Stacked가 그 위에 새로운 가치를 더할 수 있는 소스만 사용한다.

**HN 데이터 특성**
- HN은 링크 모음이다. API로는 제목, 원문 URL, 점수, 작성자, 시각, 댓글만 받을 수 있고 원문 본문은 없다.
- 원문은 URL로 직접 수집해야 한다. 유료 기사, 봇 차단, 동적 페이지, 글이 아닌 링크(GitHub, 영상, PDF) 등은 수집에 실패할 수 있다.
- 원문 수집에 실패하면 해당 글은 Stacked도 수집하지 않는다.

# 목표

## v1

- 1인 사용(나)을 전제로 한다.
- HN 글을 영어 요약 + 핵심 표현 + 문장별 번역으로 읽을 수 있다.
- 댓글의 주요 의견을 함께 볼 수 있다.
- 중요도에 따라 읽을 글을 고를 수 있다.
- 매일 자동으로 새 글이 준비된다. (단 HN의 최신글을 가져오지 않는다. HN에 게시 후 충분한 기간(3일?)이 지나 많은 사람들의 그 글에 대한 평가가 끝난 뒤 가져올지 말지 결정한다)


## v2

- 미정 (여러 사용자, 협업 필터링, 기술 공유 기능 등 후보, HN 이외의 소스 탐색)

# 에픽

> 각 에픽의 완료 기준은 해당 에픽을 시작할 때 구체화한다.

## 1. 영어 요약으로 HN 글을 읽는다

**목표**: 화면에서 HN 글의 영어 요약을 읽고, 막히는 문장은 길게 눌러 한국어로 확인할 수 있다.

**작업**
- 수집: HN 글 10개 정도
- 원문 수집: 성공한 글만 사용, 실패한 글은 건너뛴다
- LLM 가공: 영어 요약(5문장 이내), 문장별 한국어 번역, 핵심 표현(기술 용어 + 일반 표현)을 생성해 저장한다
  - 번역은 즉시 보여야 하므로 미리 생성해 둔다
  - 번역은 영어 문장과 짝지어 문장 단위로 저장한다
- 화면: 글 목록, 요약, 문장 길게 누르기 번역, 사이드 핵심 표현
- 기록: 글 클릭, 번역 누름 (나중에 중요도·난이도 판단에 쓸 데이터)
- 스키마에 출처(source) 필드를 둔다 (나중에 소스 추가 대비)

**완료 기준**
- [ ] 수집을 두 번 실행해도 같은 글이 중복 저장되지 않는다
- [ ] 화면에서 글 목록과 각 글의 영어 요약이 보인다
- [ ] 요약 문장을 길게 누르는 동안만 해당 문장의 한국어 번역이 보인다
- [ ] 요약 옆에 핵심 표현과 뜻이 종류별(기술/일반)로 보인다

**이번 에픽에서 하지 않는 것**
- 댓글, 자세히 보기
- 원문 수집 실패의 정교한 처리
- 중요도, 자동 실행, 디자인

## 2. 중요도에 따라 읽을 글을 고른다

**목표**: 중요도 높은 글을 먼저 볼 수 있다.

**작업**
- 중요도 산정 기준 정의 (아래 "중요도" 참고). 가장 단순한 기준(신뢰성)부터 시작한다.
- 중요도를 화면에 반영

## 3. 자세히 보기와 다른 사람의 의견을 본다

**목표**: 더 긴 영어 요약과 HN 댓글의 주요 의견을 함께 볼 수 있다.

**작업**
- HN 댓글 수집 (수집 시점, API 선택 결정 필요)
- 긴 요약 + 주요 의견(찬반이 뚜렷하면 나눠서) 생성
- 원문 수집에 실패한 글은 댓글 기반 요약임을 화면에 표시한다

## 4. UI 다듬기

**목표**: 보기 좋고 읽기 편한 화면.

**작업**
- 디자인·스타일링은 AI를 활용한다 ([AI_POLICY.md](AI_POLICY.md) 예외 참고)
- 데이터 연동과 표시 로직은 직접 구현한다

## 5. 매일 자동 실행

**목표**: 매일 새 글이 자동으로 준비된다.

**작업**
- 배치 스케줄링
- 실패 시 알림

# 중요도

다음 속성이 있는 글의 중요도가 더 높다.

1. **연속성**: 이전에 읽은 글의 후속 소식이나 연관된 글
2. **전문성**: 글의 전문성이 높을수록 중요도가 높다
3. **신뢰성**: 신뢰할 만한 주체가 쓴 글이나 기술 발표

추가 후보
- 영어 난이도: 내 수준에 맞는 글 (번역 누름 기록으로 판단)
- HN 점수, 댓글 수

# 열린 결정

- "읽었다"를 무엇으로 판단할지 (클릭, 체류 시간, 명시적 버튼)
- HN의 어떤 목록을 수집할지 (new / top / best)
- 요약을 언제, 몇 개나 생성할지 (비용과 대기 시간)
- 주 사용 기기 (모바일 길게 누르기 동작 고려)
