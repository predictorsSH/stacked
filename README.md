# Stacked

IT 기술 관련 이야기들이 하루에도 수백개씩 쏟아진다.<br>
진짜 중요한 정보는 아주 일부에 불과하다. 일부를 제외한 나머지는 노이즈다.
<br>
노이즈 때문에 중요한 정보를 놓치는 경우가 많다.
타이틀을 매력적으로 작성해둔 노이즈들이 많기 때문이다.
<br>
노이즈를 제외하고 사용자에게 필요한 정보들을 전달하는 일종의 Agent를 만드는게 이 프로잭트의 목표다.


# 목표

## v1

- UI에서 기술블로그, 뉴스, 긱뉴스 등의 아티클 목록이 뜬다.
- UI에서 아티클 중요도에 따라 보이는 모습이 다르다.
- 글을 클릭하면 원본 글과, 해당 글을 사용자가 읽기 쉽게 재구성한 형태로 보여준다.
- 글 목록은 1일 업데이트다. 사용자가 새로고침을 누르면 그때 업데이트 된다. 업데이트는 하루에 한번된다.

## v2

- v1 기능 고도화



# 에픽

## 1. 글 목록 화면에 보이기

**목표** : 아티클 목록을 화면에서 확인 할 수 있다.
**작업**
- 데이터 스키마 정의
- 수집, 정제, 저장 모듈 개발 (API)
- 글 목록을 확인할 수 있는 UI 개발

## 2. 중요도별로 구분하여 아티클을 볼 수 있다.

**목표** : 중요도 높은 아티클 우선 확인
**작업**
- 아티클 중요도 산정 로직 정의
- 아티클 중요도를 산정해 UI에서 구분

## 3. 재작성 모듈 개발

**목표** : 원본 글이 아닌 재구성된 글을 사용자가 볼 수 있도록 재작성
**작업**
- 아티클 원본을 이해하기 쉽고, 읽기 쉬운 형태로 재가공.
- 아티클의 타이틀도 재작성
- 아티클 원본의 링크와, 재구성된 버전을 UI에서 함께 확인 가능

## 4. 화면 UI 개발

**목표** : UI를 있어빌리티 하게 수정
**작업**
- AI에게 요청할 예정

## 5. 배치 개발

**목표** : 매일 아티클이 새로고침 되도록 배치 개발
**작업**
- 매일 아티클이 새로고침 되고, 배치가 안돌면 사용자거 새로고침 버튼을 누를 수 있도록 개발

# 중요도

다음과 같은 속성이 있는 아티클의 중요도기 더 높다.

1. 연속성 : 사용자가 이전에 읽던 글들의 업데이트 또는 연관된 다른 아티클
2. 전문성 : 글의 전문성이 더 높을 수록 중요도가 높음
3. 신뢰성 : 신뢰할만한 주체가 작성한 글, 또는 기술 발표 등은 중요도가 높음
